# Форматы файлов

## План экспериментов

UTF-8 CSV, разделитель `;`, одна запись на строку. Поддерживаются поля в кавычках и экранирование кавычки как `""`. Переводы строк внутри поля не поддерживаются. Максимальный размер плана или циклограммы — 2 MiB.

| Индекс (с 1) | Содержимое |
| --- | --- |
| 1 | Уникальный тег эксперимента |
| 2 | Файл циклограммы, расширение `.csv` необязательно |
| 3 | Комментарий, не используется алгоритмом |
| 4–5 | Kp, Ki |
| 6–8 | Коэффициент E, tauNum E, tauDen E |
| 9–11 | Коэффициент R, tauNum R, tauDen R |
| 12–13 | Имена внешних датчиков E и R, необязательны |

Числа могут иметь точку или запятую. Kp, Ki и постоянные времени неотрицательны; коэффициенты FF могут быть отрицательными. Теги сравниваются с учётом регистра. Дубликат тега — ошибка. Строки, не совпадающие с выбранным тегом, пропускаются.

Циклограмма ищется рядом с планом или в **Cycle folder**. Абсолютные пути поддерживаются. Встроенный план расположен в ресурсах `:/examples/plan.csv`.

## Циклограмма

```csv
r_time_ms;r_power_w;e_time_ms;e_power_w
0;0;0;0
15000;0;15000;3
30000;0;30000;0
```

Время — целое неотрицательное число миллисекунд от старта цикла. Значения E и R — неотрицательная мощность в ваттах. Между точками E остаётся ступенчатым, R интерполируется линейно. До первой и после последней точки канал даёт 0. Длительность цикла определяется последней точкой наиболее длинного канала.

Пара R или E может быть полностью пустой, дополнительные столбцы игнорируются. Время каждого канала должно идти по возрастанию; соседние записи с одинаковым временем объединяются, последняя задаёт значение. Частично пустая пара, обратный ход времени или неверное число отклоняют загрузку целиком.

## Вход измерений

В режиме **CSV input** укажите файл на вкладке **Input** и выберите название столбца температуры. Пример:

```csv
timestamp;temperature_c
2026-01-01T12:00:00;16.800
2026-01-01T12:00:01;16.900
```

Данные должны быть в °C. Регистр названия столбца не учитывается. Программа читает последнюю полную строку и рассчитывает управление, сохраняя результат в журнал. Она не отправляет команды оборудованию.

Источник должен завершать строки переводом строки и регулярно обновлять запись, например менять timestamp даже при постоянной температуре. Замена или уменьшение файла поддерживаются. Если последняя запись не меняется, через 5 секунд расчёт останавливается. Это проверка свежести данных, не аппаратная защита.

## Внешний CSV датчиков

```csv
timestamp;Sensor E;Sensor R
2026-01-01T12:00:00;18.000;18.000
```

Имена датчиков из плана должны совпадать с заголовками полностью, без учёта регистра и внешних пробелов. Неуказанный канал даёт 0; указанный, но отсутствующий столбец считается ошибкой. На вкладке **Input** выберите этот файл и нажмите **Monitor sensor CSV**. Для R-компенсации дождитесь свежих данных и нажмите **Capture T₀** при остановленном расчёте.

При активной R-компенсации данные также должны обновляться не реже чем раз в 5 секунд. `examples/sensors.csv` — статический образец формата, не журнал эксперимента.

## Результаты сессии

По умолчанию: `QStandardPaths::AppLocalDataLocation/sessions/yyyy-MM-dd/HHmmss_zzz`. Другой каталог:

```sh
PIDStudio --output-dir ./sessions
```

Каждый запуск создаёт `measurements.csv` и `events.csv`. Схема измерений:

```text
timestamp;elapsed_s;tag;target_c;temperature_c;error_c;p_w;i_w;ff_e_w;ff_r_w;power_w;code;sensor_e_c;sensor_r_c;baseline_r_c;running
```

`p_w` и `i_w` — составляющие PI, `power_w` — ограниченная мощность, `code` — обобщённая команда в выбранном диапазоне. При включённом квантовании `temperature_c` содержит квантованное значение. В состоянии ожидания выход и составляющие управления равны нулю. Числа записываются с десятичной точкой, время — ISO 8601 с миллисекундами.

`events.csv`: `timestamp;event;details`. События и ошибки также видны в интерфейсе. Все включённые в репозиторий данные демонстрационные.
